# AI Notes — My Use of Codex in Project B

I started Project B with my own first version of the source code, build file, results and Streamlit app. I then used Codex to review my existing work rather than create an unrelated project from scratch. I provided the official Project Brief and Week 7–9 lecture materials and asked Codex to use these official sources as the main reference points for the revision. I also requested that it preserve my first version and produce a separate revised folder.

Codex performed the majority of the detailed technical audit and implementation work. While reviewing the outputs from my first version of Project B, I also noticed several output-level omissions by comparing the results folder and CSV files with the Project Brief and Week 7–9 content. First, the first version only contained five funds, with no crypto-only funds or equal-weight benchmarks. Second, the fusion before-versus-after table and figure were absent. Third, the sentiment outputs were still primarily reported as VADER compound scores from -1 to +1 and did not contain the Week 9-style 0–100 sentiment scale for the app. I added these problems to the revision checklist. The revised project now includes 14 core funds across the equity-only, crypto-only and combined universes. Each universe contains equal weight, minimum volatility, tangency and risk parity. Sentiment Tilt Equity and MarketPulse TailGuard provide the two implemented extensions. The final results also contain the fusion before-versus-after comparison as well as the 0–100 sentiment scale for the app.

The deeper audit discovered that my original code reindexed crypto prices to equity dates before computing returns, used CAGR divided by annualised volatility as the Sharpe ratio, and could silently return default weights after an optimisation failure. Codex also discovered that the headline panel joined multiple ticker-day headlines before VADER scoring, the sentiment tilt could exceed the 20% asset cap, and the allocation tool changed missing fund returns to zero. The first `fund_weights.csv` confirmed that the sentiment-tilted fund reached approximately 31.96%. Codex identified and corrected these issues; I did not independently locate or write all the corrections.

Through Codex's explanations, I came to understand why the main portfolio corrections matter. A later AI-assisted review identified an important error in the earlier calendar advice. I then consulted the relevant Project Brief requirement and agreed that the implementation should be corrected. Crypto returns must be calculated on the crypto calendar first, and the already-computed daily returns must then be left-merged onto the equity trading calendar to produce the combined funds. Under the official Project Brief, weekend-only crypto moves are intentionally excluded rather than compounded into Monday. The final Sharpe calculation uses mean daily excess return divided by daily return volatility and annualises the ratio using the square root of 252 for equity and combined funds or 365 for crypto-only funds. Solver diagnostics are also saved so that a failed optimisation cannot silently appear successful.

The sentiment revision retains individual headlines through VADER scoring and then computes both ticker-day and equal-weight sector averages following the Week 8–9 workflow. It reports plain VADER, a small finance extension and the lecture's 0–100 sentiment scale. The descriptive full-sample z-score is kept separate from the lagged expanding signal used in trading, and the 20% cap is reapplied after the sentiment tilt.

I independently read and labelled the 150-headline blind validation sample as positive, neutral or negative. Codex checked the finished file and ran the evaluation script but did not supply, edit or retune the labels. The finance-extended model achieved 48.0% accuracy and a macro-F1 of approximately 0.428, versus 46.0% and 0.412 for plain VADER. I retained the weak 21.7% recall for the negative class as a limitation rather than treating the modest overall improvement as proof that the model was highly accurate.

My clearest personal finding came when I opened the revised Streamlit app. In Dark Mode, I saw that most of the text was barely visible and sent Codex a screenshot. Codex explained that the fixed light-background CSS conflicted with Streamlit's Dark theme and changed the app to use Streamlit theme variables. This was a problem that I personally identified while using the app.

I also learned that an AI-produced revision still needs another check. The first revised package overlooked a non-chronological date index after crypto and equity-calendar fund series were concatenated. I did not find the exact line myself, but I requested a final rule-by-rule ZIP audit, and that later audit identified the mistake in the earlier AI-assisted revision. Codex added an explicit date sort, rebuilt the results and added a regression test. This matters because cumulative growth, drawdown and app charts depend on chronological observations. The audit also found Finder metadata and cache files, which were excluded from the clean package.

After the later Brief-calendar correction, the final revision reported 24 passing automated tests, 612 monthly fund-rebalance records across core and robustness runs, no solver fallbacks and a maximum individual weight of 20%. Codex also ran the hand-in checker and an automated Streamlit smoke test in its workspace. Before submission, I will run the final tests, hand-in checker and Streamlit app on my own computer and inspect the main controls myself.

I used AI for code review, implementation support, testing and explanations. I am not using it as a substitute for my own economic interpretation. I will write and check the report's discussion, limitations, recommendations and citations in my own words, compare every reported number with the final CSV files, and make sure I can explain the methods I am presenting.
